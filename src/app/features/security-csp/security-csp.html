APPLICATION SECURITY

Content Security Policy

A browser-enforced policy that limits where page resources can load from and which scripts can run.

How CSP helps

A restrictive CSP can reduce the impact of cross-site scripting (XSS) by blocking unexpected scripts, inline handlers, and untrusted resource loads. It is an extra layer of defense; it does not replace safe output handling, authentication, or server-side authorization.

Example response header

Configure a policy as an HTTP response header on the production web server or hosting platform: 

{{ examplePolicy }}

This is an example for this app’s current external fonts and avatar. Review and tighten the allowed sources for the actual deployment. This repository has no backend or hosting-header configuration, so the example is not enforced by the development server.

What CSP does not protect

CSP does not encrypt application data or make browser storage secret. Merchant form data is currently stored in localStorage. Role-based masking in this demo controls what the interface displays, but production access decisions must also be enforced by a trusted backend.
